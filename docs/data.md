# Static data

The game has no API for several things the panels show, so the addon ships them as Lua tables in `Data/`. Most are generated by scripts in `tools/` and shouldn't be edited by hand: change the generator and run it again.

| File | What it holds | Source | Regenerate with |
|---|---|---|---|
| `Data/Schools.lua` | Each class spell's magic school, by English name and every rank's spell ID. Physical, pet, and helper spells are left out. | Forever's client spell tables (SkillLineAbility, SchoolMask) on wago.tools | `python tools/make_schools.py` |
| `Data/SpellRanks.lua` | Each class spell rank's level learned and spell power coefficients `{ level, direct, over time }`, flagged as healing or estimated. | A spell database built by `tools/forever_spells.py` from Forever's client tables, plus scaling from Blizzard's beta notes and a hand-written `EXTRA` list | `python tools/make_coefficients.py` |
| `Data/Coefficients.lua` | Not data: the code that applies the coefficients (`ns.spellPowerRows`). | | |
| `Data/Nodes.lua` | Each herb and ore node's taps and drops `{ item ID, name, chance %, count from, to }`. Quest-only drops are left out. | CMaNGOS Classic database (1.12.1) | `python tools/make_nodes.py` |
| `Data/Skinning.lua` | Each skinnable creature's drops, by creature ID. Creatures with the same loot share a list. | CMaNGOS Classic database | `python tools/make_nodes.py` (same run) |
| `Data/NodeNames.lua` | Each node's name in the client's language, mapped to the English name the node data uses. Ooze-covered nodes map to the plain node. | | Edited by hand |
| `Data/Disenchant.lua` | Disenchant results by quality, item level, and armor or weapon. | Warcraft Wiki's Classic "Disenchanting tables" | Edited by hand |
| `Data/Stats.lua` | Not data: stat recognition, rewording, and colors (see below). | | |

## The generators

All the generators use only Python's standard library.

- **`tools/forever_spells.py`** finds the newest Forever build on wago.tools (`1.6x.x`), downloads about 15 DB2 tables as CSV, and joins them into a JSON database of class spells keyed by spell ID. It follows a spell's damage through the spells it triggers and the spells its tooltip reads from. Downloads are cached in the temp folder under `prettytooltip-wago/<build>/`, because a build's tables never change. Options: `--build`, `--offline`, `--previous old.json` (report what changed), and an optional comparison with the newest Classic Era build. It has two limits. wago.tools serves tables as the build shipped, without later hotfixes. And some scaling values exist only on Blizzard's servers; those stated in Blizzard's beta notes are in `SERVER_SCALING` and used only where the client has none.
- **`tools/make_coefficients.py`** turns that database into `Data/SpellRanks.lua`. Each rank gets one direct and one over-time coefficient, the largest of each kind, because the tooltip shows one amount of each. A spell that both damages and heals is classed by the damage it names first.
- **`tools/make_schools.py`** writes `Data/Schools.lua` from the same tables. Each spell gets the school most of its ranks have.
- **`tools/make_nodes.py`** downloads the CMaNGOS SQL dump (once, or again with `--refresh`), parses its loot tables, and resolves groups and references into chances per tap. Only the nodes `Tooltips/Object.lua` knows are written.
- **`tools/make_strings.py`** writes the game's global strings for the **tests**, not the addon (see [Localization](localization.md)).

Rerun the spell generators when Forever adds or changes class spells, and commit the regenerated files together with any expected test outputs they change.

## How the data is used

### Spell power coefficients (`Data/Coefficients.lua`)

`ns.spellPowerRows(part, bonusCode, game)` returns two lists of rows for a spell panel:

1. **The split.** One row each for the direct amount and the amount over time: "Spell Power Coefficient" (or "Healing Power Coefficient"), then the share in the school's color, then base + bonus, such as `85.7% · 300 - 340 + 120`. An estimated share is marked `~`, and a per-tick amount says "each". Forever's tooltips already include spell power in their amounts, so the base is the amount minus the bonus.
2. **Rates.** The average per second and per mana.

Steps:

- **Find the rank.** By the spell ID, or by the rank its name and rank text name (`ranksNamed`). Only spells in `Data/SpellRanks.lua` that scale get a split. Another class spell gains nothing, however its text reads.
- **Read the amounts** from the description with the language's `descriptions` wordings (see [Localization](localization.md)): the first amount dealt or healed at once, and the first spread over time with its duration and tick count.
- **Pick the coefficient.** The rank's own from the data. A spell missing from the data is estimated with Classic's rules: cast time ÷ 3.5 for direct amounts (instant counts as 1.5 s, capped at 3.5 s), duration ÷ 15 for amounts over time, and Classic's split for spells that do both. Channeled spells have no rule and get no estimate.
- **Spell power** comes from `GetSpellBonusDamage(school)` or `GetSpellBonusHealing()`, unless the part supplies its own (the editor's samples do).
- **Rates** use the execute time: the cast shown (after talents and haste), at least the global cooldown, or a channel's whole duration. Per-mana rates only apply to mana costs.

### Disenchanting (`Data/Disenchant.lua`)

`ns.disenchantFor(classID, quality, level, equipLoc, itemID, game)` returns what an armor or weapon item disenchants into, or nil. Crafted wands and slots that can't be disenchanted are left out. The result holds:

- each material with its count range and chance, named and given an icon through the client by item ID;
- the Enchanting skill needed, and the player's (`game.skill("Enchanting")`);
- an expected value, when Auctionator has a price for every likely material.

### Gathering loot

`Tooltips/Object.lua` maps a node's localized name to its English key through `Data/NodeNames.lua`, then looks up `Data/Nodes.lua`. Item IDs are checked against the client's item names, so a wrong entry is skipped. `Tooltips/Minimap.lua` uses the same node lookup to show a node's required skill. Unit panels read a creature's skinning drops from `Data/Skinning.lua` by the creature ID in its GUID.

### Stats (`Data/Stats.lua`)

| Function | Purpose |
|---|---|
| `stats.read(text)` | Recognizes a stat line in the client's wording ("+6 Intellect") and returns its key, sign, and amount. |
| `stats.rewrite(text)` | Turns an equip sentence into stat lines: "Equip: Increases healing done by up to 20 and damage done by up to 10…" becomes "+20 Healing Power" and "+10 Spell Damage Power". Rules come from the game's `ITEM_MOD_*` strings and the language's `statWordings`. |
| `stats.itemWording(text, proc, colors, markers)` | Gives an item line's two wordings: `display` for panels and `lite` for the game's own tooltip, plus how many lines it became. |
| `stats.styleStat`, `styleDamage`, `styleEffect` | Color a stat by category, school damage in school colors, and effect numbers like spell descriptions. |
| `stats.CATEGORIES` | The soft category colors, each with a lighter shade for the stat's name. The style editor can override them. |
